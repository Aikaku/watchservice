## 1. 평가 방법

### 데이터
- 파일: `ai_server/synthetic_ransomware_dataset_30000.csv` (합성 데이터 30,000건)
- 라벨 분포: 정상(benign) 22,568건 (75.2%) / 랜섬웨어 7,432건 (24.8%)
- 입력 피처: 백엔드 `EventWindowAggregator`가 3초 윈도우마다 계산해 보내는 9개 피처와 같다.

### 분할
학습 스크립트 `ai_server/untitled21.py`와 **같은 조건**으로 나눴다.

```python
train_test_split(X, y, test_size=0.2, stratify=y, random_state=42)
```

- 학습 24,000건 / **테스트 6,000건** (정상 4,514 + 랜섬웨어 1,486)
- `random_state=42`로 고정했기 때문에 누가 돌려도 같은 테스트셋이 나온다.

### 경위
- 학습 스크립트는 지표를 화면에 출력만 하고 저장하지 않아서, 남아 있는 수치 기록이 없었다.
- 그래서 저장된 모델 파일을 같은 테스트셋에 다시 돌려 지표를 재현했다(2026-11-17).
- 환경: Python 3.9, xgboost 2.1.4, scikit-learn 1.6.1

## 3. 시스템 판정 기준별 성능

AI 서버(`api_server.py`)는 score에 따라 등급을 매긴다: **0.70 이상 DANGER**, **0.50 이상 WARNING**, 그 미만 SAFE.

| 기준 | 임계값 | 탐지율 (TPR) | 오탐률 (FPR) |
|------|:------:|:------------:|:------------:|
| WARNING 이상 | 0.5 | 88.56% | 2.41% |
| DANGER | 0.7 | 83.85% | **1.46%** |

- DANGER가 되면 이메일과 긴급 전체화면 경보가 나간다. 그래서 오탐을 줄이는 쪽(1.46%)으로 기준을 더 높게 잡았다.
- WARNING은 탐지율을 우선해서 의심 활동을 더 넓게 잡는다.

## 4. 피처 중요도 (gain 기준)

| 순위 | 피처 | 중요도 | 의미 |
|:----:|------|:------:|------|
| 1 | `file_encrypt_like_count` | **65.4%** | 암호화로 의심되는 파일 수 |
| 2 | `changed_files_count` | 15.2% | 변경된 고유 파일 수 |
| 3 | `file_rename_count` | 4.8% | 이름이 바뀐 파일 수 |
| 4 | `file_write_count` | 4.1% | 쓰기 수 |
| 5 | `random_extension_flag` | 3.2% | 의심 확장자 집단 발생 여부 |
| 6 | `file_delete_count` | 3.2% | 삭제 수 |
| 7 | `file_read_count` | 3.1% | 접근 수 |
| 8 | `entropy_diff_mean` | 0.5% | 엔트로피 변화 평균 |
| 9 | `file_size_diff_mean` | 0.5% | 크기 변화 평균 |

**해석**
- 모델 판단의 약 2/3가 `file_encrypt_like_count` 하나에 달려 있다.
  - 그래서 프로젝트 초기(03-06, 03-11)에 이 피처의 계산을 집중적으로 개선했다: 3구간 엔트로피 샘플링, 절대 엔트로피 7.2 기준, 스트림 암호 패턴. 자세한 내용은 `FEATURE_CHANGES.md` 참고.
  - 바꿔 말하면, 백엔드가 이 값을 정확히 계산하지 못하면 탐지 성능이 크게 떨어진다.
- `entropy_diff_mean`과 `file_size_diff_mean`은 단독으로는 영향이 작다. encrypt-like 판정 안에서 이미 엔트로피와 크기 변화를 쓰고 있기 때문으로 보인다.

## 한계와 주의사항

1. **합성 데이터다.** 실제 랜섬웨어 샘플에서 뽑은 데이터가 아니므로, 실제 환경의 성능은 이보다 낮을 수 있다. 정상 사용 패턴(대량 압축, 빌드, 동기화 등)도 합성 데이터에 충분히 반영되지 않았을 수 있다.
2. **학습 조건이 같다는 가정이 있다.** 저장된 모델이 위 분할의 학습셋(80%)으로 학습됐다고 가정한 값이다. 학습 스크립트의 흐름상 그렇게 보이지만, 만약 전체 데이터로 다시 학습한 모델이라면 테스트셋을 이미 본 셈이라 수치가 실제보다 높게 나온다.
3. **이진 분류다.** 랜섬웨어 종류(LockBit, WannaCry 등)는 구분하지 못한다. 이 때문에 패밀리 상세 정보 기능을 제거했다(2026-05-14).
4. **추론 시간은 모델 연산만 잰 것이다.** 실제 탐지까지 걸리는 시간에는 3초 윈도우 집계와 Railway 서버까지의 네트워크 왕복이 더해진다. 이 전체 시간은 측정하지 않았다.
